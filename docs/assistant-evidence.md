# Ask UofG evidence policy

This prototype never labels AI text verified or official advice. Only explicit `url_citation` annotations attached to assistant output are evidence candidates; web-search consulted sources are not. Every paragraph in every text block must have an in-range citation. Invalid annotations, incomplete/malformed output, uncited paragraphs, conflicting inline URLs, homepage citations and non-University URLs cause the entire answer to be withheld. Query/fragment URLs are conservatively rejected. Source labels use the actual host/path rather than model-supplied titles. No new page-fetching or redirect-following service is introduced.

A conservative topic screen requires at least one meaningful question word in a cited URL path. This catches obvious irrelevant citations, but creates false negatives (synonyms, opaque paths, non-English questions). It is an abstention heuristic, not semantic verification. No result is returned as verified guidance. A model can still cite a legitimate but irrelevant page with matching words. Each paragraph may contain multiple claims; structural coverage does not establish claim-level support, accuracy, currency, completeness, or applicability to a student's circumstances. Redirect destinations and page contents are not independently checked. Public University subdomains may contain historic or user-authored material. Human review and stronger retrieval/claim validation remain necessary before a University-wide launch.

Sensitive topics matched by a conservative local keyword screen (including immigration, eligibility, appeals, medical and safeguarding enquiries) bypass the model and receive fixed student-service signposting. This screen is English keyword based and can miss paraphrases or over-refer innocent questions. The assistant is not a crisis triage system; the wellbeing link must not be treated as emergency support. No personal advice or eligibility decision is generated by this route. The client discards non-cited/invalid source responses and displays its own fixed uncertainty message, plus separate student-service and wellbeing links. These links are navigation, never evidence. Client validation cannot authenticate a compromised server.

## Repeatable evaluation

Run `npm test` for offline backend regression tests, the nine-question `server/assistant-evaluation.json` set and TypeScript checks. All upstream responses are synthetic; no API key or live paid call is needed. Run `npx playwright test e2e/ask-uofg.spec.js` for mocked browser checks in desktop/mobile viewports. Missing, malformed, misleading, irrelevant and manipulated attribution cases exercise deterministic policy, not real model quality.

For an optional supervised live evaluation, reuse the questions, record date/model, inspect every cited page and each claim, and score relevance, currency, support, appropriate abstention and service routing. Add normal questions about academic support, campus navigation and wellbeing navigation. Check ambiguous fees/deadline questions and adversarial page/user instructions. Never use real student private data. Live runs incur charges and are not CI requirements. A matching URL word or syntactically valid citation alone must never count as factual success.

Existing API credential isolation, origin restrictions, rate limits and loopback binding remain. Dependency security and physical-phone connectivity are separate workstreams.
